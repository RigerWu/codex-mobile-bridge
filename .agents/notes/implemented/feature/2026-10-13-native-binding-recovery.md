# Agent Note: 原生设备绑定恢复

Status: implemented

## Problem

手机原生壳的 WebView Cookie 可能在应用升级或系统清理后丢失。服务器仍保留已认证、可撤销的设备会话，但原生壳没有独立的安全副本，用户因此需要重新登录或扫码。

## Decision

两端只备份已通过 `/api/auth` 确认的 `trustedDevice` 会话令牌，按保存的电脑地址索引。Android 使用 AndroidKeyStore 的 AES-GCM 密钥加密副本，密文保存在应用私有偏好设置；iOS 使用 `WhenUnlockedThisDeviceOnly` Keychain 项。令牌仍由网关或中继的现有会话表撤销，不新增密码、二维码或不可撤销的第二套凭据。

WebView 加载前，如 Cookie 缺失或与安全副本不符，原生端用只读、同源、禁止重定向、限时限量的 `/api/auth` 检查当前 Cookie 和安全副本。首次登录时先记录完整 Cookie 快照，待网关返回 `cookieName` 后才选择对应令牌；旧名迁移只接受同一令牌，不因同主机其他网关的 Cookie 误存。当前 Cookie 有效则保留并在正常认证回调中更新副本；安全副本被服务器确认有效且其 Cookie 名称属于该网关时才恢复。无 `cookieName` 的旧直连网关及中继仅接受旧 Cookie 名。明确无效时删除副本，网络错误时保留以供下次尝试。已打开页面收到 401 时，每次失效周期只触发一次原生校验和只读页面重新加载；恢复不重放消息或写请求。异步校验完成时再次检查设备凭据、页面代际和当前 Cookie，避免退出或移除后的迟到结果复活会话。显式退出与移除删除该地址的安全副本及对应 Cookie。

## Alternatives considered

重新保存密码或可复用扫码载荷能够再次登录，但扩大了长期秘密和配对能力。另设恢复令牌及 HTTP 端点可以与登录令牌分离，却需要新的服务器存储、撤销和中继协议；现有原生设备会话已经持久且可撤销，复用它更小。

## Consequences

Cookie 丢失后，仍有效的绑定可在加载登录界面前或已打开页面遇到 401 时恢复；服务器撤销后不能恢复。首次连接会增加一次至多五秒的只读校验，离线时仍进入原有页面错误路径。Android KeyStore 或 iOS Keychain 不可用时不会把明文令牌写入普通偏好设置。真实设备上的存储与系统清理行为仍需设备验证。

相关 Cookie 名称和旧版兼容规则见[网关会话 Cookie 隔离记录](../bug-fix/2026-10-13-gateway-cookie-namespace.md)。历史笔记只有该记录部分重叠；它规定网关命名，本篇规定原生安全副本与恢复时序。
